## 🔬 How I Approach Problems

I don't like treating software as a collection of isolated features.

I prefer to understand the **problem, the underlying system, and the constraints** first.

Then I think about:

**How should it work?**  
→ **What should the architecture look like?**  
→ **What can stay simple?**  
→ **What should be reusable?**  
→ **How can it evolve later?**

That usually leads me toward software that is modular, lightweight and extensible rather than overly complicated from the beginning.
